# 规则引擎能力清单

本文件界定规则校验组件，不取代“分层知识—实体打标—修改时召回—验证 Agent 效果”的项目目标。完整路线的本轮实现见 [分层知识与实体标签](TAGGED-KNOWLEDGE.md)。

当前范围是 Java 单文件、线程池领域、26 条规则。原子规则主要按代码特征匹配；任务描述不直接驱动 Rules 匹配，新增能力可由调用方显式提供 featureHints。文档到 YAML 的整理及新 checker 的编写仍由开发者完成。

“结构检查”指可直接检查已解析 API 和参数；“有限模式”指还依赖类型关联、别名或局部路径，诊断需要结合上下文；“建议”不作为已证实违规。以下边界适用于每条规则，而非只适用于尚未实现的规则。

| --- | --- | --- |
| TP-CREATE-001 | 结构检查：识别标准 Executors 快捷工厂 | 自定义工厂内部实现、采用无界资源是否有充分业务限制 |
| TP-CREATE-002 | 有限模式：方法内创建池与字段 / Bean 资源归属 | 临时池是否有合理生命周期、跨文件托管 |

| TP-REJECT-003 | 有限模式：提交位置的拒绝异常处理 | 调用链如何传播、是否破坏主流程、补偿是否有效 |

| TP-SHUTDOWN-002 | 有限模式：等待结构、一层私有等待 helper、Java 21 close 等 | 所有分支与重复 / 并发关闭、超时后失败报告、实际资源终止 |
| TP-SHUTDOWN-003 | 有限模式：有界路径中恢复当前线程中断或重抛 | 复杂控制流、外部 helper、再次中断和运行中任务响应 |
| TP-SHUTDOWN-004 | 结构检查：直接忽略或局部列表不读取 | 所有别名 / 重赋值、记录是否充分、任务是否补偿、Future 是否完成 |
| TP-MONITOR-001 | 有限模式：按池关联已知监控 getter / 支持的委托 | 业务计数与真实任务一致性、采集及告警效果 |

## 诊断该如何使用

- 显式 API / 常量问题适合形成可定位提醒；涉及所有权或路径的 finding 是需要核实的风险，不是完整证明。
- TP-SHUTDOWN-004 和取消队列检查是 warning。warning 也可能对应特定业务契约下的严重缺陷；不能只因没有 error 就宣称可以交付。
- `validate.status=complete` 表示所选 checker 已执行，不表示 26 条规范的全部语义均得到证明。单条 `passed` 仅表示该 checker 没有发现其覆盖模式下的问题。
- `retrieve` 的预算裁剪会省略部分规则；`validate` 默认重新分析并检查适用规则，不局限于此前注入模型的规则子集。只传 ruleIds 时，则只检查显式选择项。
- AST 语法解析不能替代 javac；编译通过不能替代实际业务回调、取消、关闭与并发场景验证；自动验证也不能替代完整任务约定审查。

目前最合适的使用方式是通过 CLI / API 展示适用规范与风险证据，配合编译和业务测试辅助审查。暂不把它作为 Cline 自动修改或独立批准交付的依据。复盘及下一步边界见 [规则覆盖复盘](RULE-COVERAGE-REVIEW.md)。
